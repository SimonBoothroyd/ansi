# Tech debt tracker

Known, deliberate debt — what someone still owes. Add a row when you knowingly
cut a corner; delete the row when you fix it.

Three rules keep this a queue rather than an archive. A row whose Plan reads
"nothing to do", or whose Debt begins "Paid" / "Retired" / "Shipped", does not
belong here — a thing that was deleted is recorded in the plan that deleted it.
A row longer than one screen is a design doc wearing a table cell. An unbuilt
*feature* is not debt; it lives in [`backlog.md`](./backlog.md). There is no
date column: when a row was noticed is git's business, and what it costs is
this file's.

| app/test | **The write-guard invariant is held by a regex over source text.** `no_bare_repo_write_test.dart` derives the write set from the repository interfaces, then walks enclosing parentheses to decide whether a call sits inside `ref.write`. It is defeated by an aliased receiver nested inside something else, by a stored function reference (`final f = repo.deleteSection; f(id);`), and by a string literal containing parentheses. Six allow-list entries carry deliberate exceptions with reasons. | A determined author, or an unusual call shape, slips a silent write past CI. | The same rule as a `custom_lint` in `packages/ansi_lints/` resolves the invoked element instead of matching text, and puts the squiggle in the editor. It would be the repo's first in-house pub package and must respect the load-bearing `custom_lint 0.8.x` / `riverpod_lint <3.1.0` pin — worth it only if the regex is actually evaded. |
| sync | **A dropped write is reported, not recovered.** The banner names the table, the operation and the server's code, and "I've seen this" retires the notice — it re-queues nothing, because the server refused the write and would refuse it again. Re-saving what the write changed is the only fix, and the user has to know what that was. | Someone taps through the banner believing it repaired something. | Only worth more if a drop is ever seen in the wild. The honest upgrade is naming the *row* rather than the table (`"Chicken Curry"`, not `recipe`), which needs a local lookup by id at report time. |
| sync/test | **Sync is untested against a genuinely failing or contended stack:** the offline-queue drain on network loss (airplane mode → reconnect), a true two-client concurrent-edit session (LWW and independent-row union, spec §3), and the escalation the banner exists for — five minutes of upload errors becoming a banner, and `Try now` reconnecting. The states, thresholds and copy are unit- and widget-tested over an overridden provider; `uploadData`'s put/patch/soft-delete mapping is unit-tested against a real `ps_crud`. | A wiring mistake between `statusStream` and the banner shows as an app that stays quiet in exactly the case the front was built for; a regression in reconnect or conflict handling slips entirely. | One errand: drive the sim with the local PowerSync container stopped, read the Shop line and the banner, then reconnect. A two-client session needs two sim clones against the local stack. |
| auth/dev | **Ghost users after `supabase db reset`, on the cached-household path only.** The onboarding path is handled — `ensure_onboarded`'s `23503` classifies as `accountMissing` and `/connecting` offers an honest Sign out. `_reconcile` (session.dart) hits the same ghost failure and deliberately swallows it, publishing `SessionReady` on the stale cached household, because flipping a live session into an error from a background reconcile would break the offline-first contract. | A dev signed in *before* the reset sees an empty-but-working app instead of the sign-out offer, until they sign out by hand. | The surface exists (`AnsiSyncBanner`, hosted once by the tab shell, advisory and never a state flip). What is left is the hook-up: an `accountMissing` case fed by `_reconcile`. |

Contract: [`search-and-matching.md`](../design-docs/search-and-matching.md). |
