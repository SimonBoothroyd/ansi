The band and the list open the same page in two postures. A row in the aisle sections opens as a row — the ingredient page’s fact sheet, with ⋯ ▸ Edit behind it, exactly as a recipe opens from the Library. A row in the band is a work queue entry that has already named what it is short of, so it opens the fields; a fact sheet repeating “needs macros” would put a menu between the queue and the thing it exists for.

two different sentences, not one. A bare stub needs macros — nothing has filled it in. One that has numbers nobody has said yes to needs completing, and the tag says which machine put them there — usda prefilled or barcode prefilled. The band is a work queue, so it names the kind of fill waiting for a human; the food’s own name is on the row below, and no id or code is printed either place. Reading “needs macros” over a row full of macros is the band lying about its own contents

the word before the name is where the name came from, not what the stamp encodes: usda · for a pick, barcode · for a scan of that pack — the brand and product name as a shelf prints them. Neither prints the key inside the stamp; an FDC id and a GTIN are lookups into databases the reader does not have

the source line appears only where there is one: a manual row shows exactly what it shows today. No name, no line — a row filled before the label column existed carries a stamp and nothing to say, and says nothing rather than inventing a name

edited · leads the line when a human has overridden the numbers, so the scan also shows which rows are no longer the machine’s

the picker is deliberately left out: it is a search surface, and a description under every row is noise while you are typing

it costs no read: the vocabulary query already selects the column, and the same rule prints the same line in the import review’s identity cell
