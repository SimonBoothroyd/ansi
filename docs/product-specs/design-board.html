Re-traced from shipped code — 2026-08-31

These frames were redrawn line-by-line from what step 8 actually shipped (import_view.dart, reconciliation_view.dart, recon_line_card.dart, method_step_text.dart). The earlier frames drew a triage → preview → commit split; driving it for real, the split read as ceremony, so it merged into one always-editable “Review recipe” screen. There is no triage step, and no separate preview — the review screen is the preview.

What survives from the original design: the three-part line (amount · ingredient · notes), resolve-once identity, the seeded picker that never opens blank, the 7.7 quantity + unit-chip sheet as the one amount editor, and a read-only method in v1. What changed: the match band now sets a line’s starting state (auto adopts its top candidate; suggest and none start unresolved) rather than choosing a screen; amount + notes stay greyed until an ingredient is matched; the ingredient’s allowed units are enforced with inline “did you mean” unit chips (five, then a fold); a line can be dropped in place and undone; and Save is gated on every kept line being valid.

Behaviour spec: docs/product-specs/import-and-matching.md §8. Grouped repeat uses no longer appear during review (one card per source line); they re-join on the recipe page as one row — “2 cloves + 1 clove”.

Placement — below the list, where the step-2 Recipe frame first drew the strip: it reads as the sum of the lines above it, and it stays clear of the scaler. A static figure sitting under a stepper would invite the reading that the stepper drives it — and it does not: the panel is per serving, so scaling to 8 doubles every line and the servings both, leaving a serving unchanged. Chips are id refs folded at render, never text matched. Numbers derive live off the line item and scale with servings: first mention only, a step-named portion wins where the prose named one, and a collective chip never shows a number — it names its constituents in smaller chips instead, so “onion mixture” can’t hide what went in.
